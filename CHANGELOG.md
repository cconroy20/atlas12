# ATLAS12 + SYNTHE — Modernization Ledger

The complete record of the translation from Robert L. Kurucz's Fortran 77
originals: every structural, numerical/physical, and hygiene change, with
design rationale, validation numbers, and post-mortems.  A compact
current-state summary lives in the README ("Translation from Fortran 77"
section); open items are tracked in [atlas_to_do.md](atlas_to_do.md).

Entries within each section are in rough chronological order.  Where a
later entry revisits an earlier one (e.g. a flag default changed after
further hardening), the later entry stands.

## Structural

- Free-format Fortran 90 source; explicit typing throughout; `-r8` flag removed
- 58 COMMON blocks consolidated into two modules (`mod_parameters`, `mod_atlas_data`)
- 829 EQUIVALENCE statements eliminated
- Full GOTO elimination pass: 38 → 0 active GOTOs across all four files, including a refactor of the `JOSH` radiative transfer solver
- Command-line argument parsing replaces card-based input for ATLAS12 driver options
- The `mklinelist` line-list preprocessor (formerly the standalone `synbeg | rgfall | rpredict | rmolecasc | rh2ofast` shell pipeline) absorbed into the SYNTHE executable as `mod_mklinelist`, dispatching from a single plain-text `lines.list` manifest
- SYNTHE three-program pipeline (XNFPELSYN, SYNTHE, SPECTRV) merged into a single executable with all inter-stage data flow in memory; intermediate binary scratch files (`fort.9`, `fort.10`, `fort.13`, `fort.14`, `fort.15`, `fort.93`, `spectrv.input`) eliminated
- ASCII spectrum output written directly by SYNTHE (`.spec`), eliminating the standalone `syntoascanga` post-processing step

## Numerical and physical

- Atmosphere state arrays (T, P, ρ, χ, populations) promoted from REAL(4) to REAL(8)
- Physical constants consolidated into `mod_constants` with CODATA 2018 values, replacing ~130 scattered literals
- Atomic partition functions replaced with the Barklem & Collet (2016) tabulated U(T) calculated by direct NIST level summation, covering Z = 1..92 in ionization stages I–III; the legacy Kurucz hand-selected few-term sums used by `PFGROUND` (the low-T floor in `PFSAHA`) and the generic `NNN` interpolation table are retained as an internal safety net but are no longer the production data source.  Iron-group partition functions (Z = 20..28) still flow through `PFIRON` for its pressure-lowering correction, but the unperturbed POTLOW = 0 baseline is now anchored to B&C
- Metal continuum bound-free opacity overhauled: a new `CONT_METAL_OPACITY_TOPBASE` dispatcher replaces the legacy collection of analytic Seaton/Peach fits (Li1OP, C1OP, MG1OP, AL1OP, SI1OP, FE1OP, …).  `MBF_TOPBASE` supplies 30 species (neutrals and first ions of Li, Be, B, C, N, O, F, Ne, Na, Mg, Al, Si, S, Ar, Ca) from R-matrix Opacity Project cross sections processed by Allende Prieto, Hubeny & Lambert (2003, ApJS 147, 363) into resonance-averaged 3%-log-spaced grids; `MBF_HIGH_ION` supplies higher ionization stages and Coulomb free-free from a filtered subset of `hotop.dat`; `FELO_OPACITY` supplies Fe I and Fe II from Iron Project / Opacity Project R-matrix calculations (Bautista 1997 for Fe I, Nahar & Pradhan 1994 for Fe II, sourced from the TLUSTY model atoms).  Toggleable via `USE_TOPBASE_MBF`; the legacy path is preserved for reference.  Known limitation: TOPbase identifies levels by LS term without resolving J, so per-species opacity carries a U_TB/U_BC factor of a few percent for most species (≲13% for the worst case, Ar II)
- Solar reference abundance pattern is now selectable at the command line (`solar=name`).  The compiled-in default remains Anders & Grevesse (1989), defined once in `mod_atlas_data` and shared by ATLAS12 and SYNTHE; `solar=` replaces the abundance table carried by the input model file while preserving its relative [M/H] offsets, and `zscale=`/`abund=`/`heabnd=` overrides apply on top.  Additional named scales are stored as log-ε tables and converted internally (`LOGEPS_TO_ABUND`); registered scales: `ag89` (Anders & Grevesse 1989), `agss09` (Asplund et al. 2009), `berg25` (Bergemann, Lodders & Palme 2025, with A(He) = 10.922 from the published compilation).  (An earlier changelog entry here claimed the default had been switched to Asplund et al. 2009 — that change was never made; the code default has always been AG89.)
- Hydrogen line profiles now use the Stehlé & Hutcheon (1999) MMM tabulated Stark broadening profiles via `hydrogen_line_profile`, replacing the Kurucz–Peterson (1982) analytic approximation; the K–P path is retained as a fallback for atmospheric layers exceeding the Inglis–Teller density limit, controlled by the `USE_KP_HYDROGEN` flag
- Voigt function evaluated via Weideman (1994) N=32 rational approximation of w(z) plus Humlíček (1982) R₁,₂ asymptotic, replacing the Kurucz three-regime table approximation that had ~4% error at the a = 0.2 regime boundary.  Accuracy is now ~10⁻⁵ relative across the full (a, v) plane with no regime boundaries
- The H⁻ bound-free photodetachment cross section in `HMINOP` replaced: the Mathisen (1984) / Wishart (1979) / Broad & Reinhardt (1976) 85-point table is superseded by McLaughlin, Stancil, Sadeghpour & Forrey (2017, J. Phys. B 50, 114001), resampled onto 116 points.  The old table ran ~0.1–1.4% high through the optical (growing toward 8000–9000 Å); the swap removes a ~1% optical continuum offset against Korg, which adopts the same source (the free-free table — Bell & Berrington 1987 — was already common to both codes, isolating the difference to the bound-free data).  The resampling reproduces the smooth optical/IR continuum to <0.05% under the code's own MAP1 interpolator; the narrow far-UV Feshbach resonance (113.4 nm, ~0.02 nm wide) is deliberately represented by its broad envelope only — a table fine enough to resolve it would ring under MAP1, and it is negligible for the continuum.  The non-LTE H⁻ polynomial in `STATEQ` is untouched (the non-LTE branch is unused in production).  Below the free-free table's 1400 K edge, `HMINOP` extrapolates linearly in θ = 5040/T — verified against the table's own curvature to ≤2% at 1200 K and ≤7% at 1000 K; a literature check found no replacement source at stellar temperatures (the Schleicher et al. 2008 low-T fit runs ~40% high)
- H₂ partition function read from an external data file rather than hardcoded
- The `JOSH` scattering solution is now a direct dense solve of the 51-point integral-operator system (I − diag(α)·Λ_J)·S = (1−α)·S̄ via `SOLVIT`, replacing the Gauss–Seidel Λ-iteration.  The iteration stalled against its 50-sweep cap once the scattering albedo α exceeded ~0.99 across the grid — 0.3% error in S at α = 0.99, 10% at α = 0.999, accepted after a warning — and its 10⁻⁵ early-exit tolerance quantized the response of every scattering solve, leaving discontinuous noise in H_ν at the tolerance level.  The direct solve is exact at comparable cost (one 51×51 LU per frequency) and reproduces the iteration to its own tolerance wherever the iteration converged (`workdir/pfverify/josh_verify.py`, Test D)
- Optional Steffen (1990) monotone-cubic quadrature for `INTEG` (developer flag `IQUAD = 1` in `mod_atlas_data`), the routine that builds τ_Ross, the per-frequency τ_ν, P_rad, and the height scale.  The legacy blended-parabola quadrature (`PARCOE`) integrates a 5-decade exponential on real model grids with 1.3% (solar) to 11% (2800 K) maximum error — only ~2× better than a trapezoid — while the Steffen cubic is 3–6× more accurate and its monotone interpolant keeps τ scales monotone with no overshoot (`workdir/pfverify/josh_verify.py`, Test C).  The quadrature error is concentrated in the deepest layers, so switching moves converged structures mainly at the grid bottom: ≤1.5 K in cool/warm stars (convection pins the deep adiabat) but 0.1–0.5% of T in hot-star radiative envelopes (47–105 K at 8000–40000 K), with equal convergence quality and negligible emergent-flux change.  The default remains the legacy quadrature
- Partition-function tables (H₂ and Barklem & Collet) evaluated with natural cubic splines instead of (log-)linear interpolation.  The interpolation kinks at table nodes, sampled by the EOS finite-difference stencil, imprinted spurious structure on ∇_ad that F_conv ∝ (∇−∇_ad)^{3/2} amplified into large local flux errors in cool-dwarf deep convection zones.  Node values, boundary behavior, and hot-star fallbacks are unchanged (verified by the `workdir/pfverify/` battery); converged structures shift by ≲0.5 K
- Molecular equilibrium network extended and repaired.  `molecules.dat` gains ten diatomics (CrO, CrS, TiN, TiS, TiH, ScO, YO, ZrO, LaO, MnH) with Sc, Mn, Y, Zr, La as new network elements, refit from Barklem & Collet (2016) Table 7 by the new `tools/fit_molecule_keq.py` (kept in-repo; `--validate` regenerates all pre-existing BC16 rows exactly); Li/Be/B gain ionization stages; then phosphorus, the metal halides, and a completeness pass (KH, NiH, CoH, CuH, ZnH, ScS, YS, LaS, NaO, KO, SiF, SiCl, SF, BeO, BeF, BO, BF, BN, BS).  Three bugs fixed on the way: the Y I and Zr I ionization potentials were ~0.2 eV high in `ionpots.dat` (~2× the neutral fraction at 3500 K), Co I's by 165 cm⁻¹, and `READMOL`'s species-code decoder misread any trailing digit pair ≥ 50 (LaO = 857.00 decoded as 9, −43).  The design gap behind the largest effect: under `IFMOL=1` charge conservation sums network species only, so elements absent from `molecules.dat` contribute nothing to n_e — Co, Ni, Cu and Zn therefore enter as pure atom/ion rows, recovering +0.5–0.7% n_e through the solar line-forming layers.  Effects: the solar photosphere cools 1–3 K near τ ≈ 1 and blue/UV flux moves ~0.1% (1%+ in the strongest line cores); ZrO, LaO and YO lock ≳99.9% of their elements at 2500 K, collapsing the neutral resonance lines by up to 10⁴; boron is ~99.9% BO at 2500 K, its 2090 Å doublet previously computed fully atomic.  Legacy polyatomic rows audited against NIST-JANAF: 10 of 12 agree to ≤0.09 dex, with MgOH and HO₂ refit D0-consistently
- NLTE departure coefficients for named transitions in SYNTHE (`mod_nlte`, `NLTE_MODE` in `mod_parameters`, 0 = off and default, 1 = on).  SYNTHE is an LTE synthesizer whose transfer step is handed `SLINE = B_nu`; that is wrong for resonance lines of minority species, most sharply the alkalis (Olander et al. 2021 measure −0.06 to −0.37 dex on K I in M dwarfs).  Kurucz anticipated it — `gfall` reserves NBLO/NBUP columns and `CODEX` whitelists 17 species — but the preprocessor that filled them was never ported, so the hook was dead.  Given `b_l`, `b_u` and `x = h nu_0/kT`, opacity becomes `kappa_LTE * b_l * [1 − (b_u/b_l)e^−x]/[1 − e^−x]` and the source function `(2h nu^3/c^2)/[(b_l/b_u)e^x − 1]`, both exact rather than Wien-limit.  These multiply to `kappa*S = b_u * kappa_LTE * B_nu * (1 − e^−x)`, which is what makes the retrofit cheap: SYNTHE accumulates one summed line opacity per (lambda, depth), so all that needs tracking beside it is the opacity-weighted DEVIATION of the emissivity from LTE, which vanishes identically for every LTE line — one extra accumulator, allocated only when NLTE is on, and a source function that is automatically the right opacity-weighted mean where an NLTE line blends with LTE neighbours.  `JOSH` is untouched.  Eligible transitions are matched on species plus BOTH level energies rather than wavelength, so every hyperfine component of a multiplet is tagged with one pair of coefficients.  Also adds continuum tau_5000 on the model's own layers (`tau5000_sv`), which an `.atm` did not carry and which is what lets grid departures be placed on our layers.  `NLTE_MODE = 0` reproduces the pre-change binary bit for bit
- The NLTE data pipeline, three stages of which only the first is expensive.  `tools/nlte_extract_grid.py` makes one streaming pass over a published grid — the Na I grid is a 15.9 GB ZIP64 member holding 57.1 GB / 436,255 records, and deflate is not seekable — keeping tau_5000 and the 10 lowest levels of every record: 32.6 min, a few hundred kB of memory, 1.0 GB out.  Two format properties make that cheap, both verified first: records are FIXED STRIDE, and the wanted levels sit at the FRONT of each record.  `nlte_build_index.py` then writes the parameter lookup and `nlte_build_runtime.py` merges the two into the single self-contained file SYNTHE reads (789 MB), dropping the 27% of records the index cannot reach.  Stages 2–3 take seconds, so any policy change is a local rebuild; only widening past ten levels needs the download again.  SYNTHE interpolates `b` over five axes — Teff(32) × log g(13) × [Fe/H](15) × v_turb(4) × dNa(31), 41% filled — reading only the ≤32 corner records (~79 kB).  Two things the interpolation must handle: every corner carries its OWN tau_5000 grid, so corners are placed on this model's tau before combining; and corners can be missing, so absent weight is dropped and the rest renormalised with the surviving fraction reported rather than absorbed.  One trap recorded: the HIGH levels of the source are NOT clean (thousands of non-finite values per record across the full 290-level block), while levels 1–10 are finite everywhere
- Two constraints the published grid imposes, recorded because neither is a choice.  [alpha/Fe] is not an axis: these are MARCS `_st_` standard-composition models in which alpha is a deterministic function of [Fe/H], so only 15 ([Fe/H],[alpha/Fe]) pairs exist of 75 possible and there are ZERO matched pairs differing only in alpha — an alpha-enhanced model necessarily receives `b` computed at the standard alpha for its metallicity.  And MARCS is plane-parallel only at log g >= 3, 100 per cent spherical below, while ATLAS12 is plane-parallel throughout; giants therefore use spherical models at 1 Msun, every cell carries a geometry flag, and mixing them across the log g 2.5/3.0 boundary is warned about.
- FIRST RESULTS with Amarsi et al. (2020) coefficients on our structures, and the two ends of the HR diagram move in OPPOSITE directions.  In the Sun b(3s) climbs to 2.35 near the top while b(3p) stays ~1, so S_l/B_nu = 0.49: the textbook photon-loss picture, cores deepening 2.3x (D2) and 2.7x (D1), EW +3.4%, a negative abundance correction matching Lind et al. (2011) in sign and size.  In a 3000 K dwarf the sign reverses: b(3s) is pinned at 1 — Na I is the dominant stage, so the ground state holds essentially the whole population and cannot depart — while b(3p) climbs to 2.3–2.6, giving a source function exceeding Planck and cores that FILL IN rather than deepen.  A third point at 4000 K places the crossover: the sequence runs S_l/B_nu = 0.49 → 0.81 → 2.38, so the mechanism inverts between 4000 and 3000 K, inside the Mann ladder's range.  The broadband consequence is not monotonic with the core effect, because it depends on how saturated the window already is: median flux change over 5886–5903 Å is −0.02% (Sun, core-confined, −63% in the core), −2.07% at 4000 K — the largest, because there the window is blanketed but not yet saturated — and +4.97% at 3000 K.  CAVEAT, and it is not small: the grid's MARCS atmospheres stop 1.1–2.0 dex of column mass short of ours, so 15–27 outermost layers hold an endpoint `b` and the cores form above it.  Every number here is a lower limit; fixing it needs `b` computed on our own structures
- NLTE extended to Mg I and Ca I/II, and the machinery is now per-element.  `mod_nlte` carries an array of `grid_t`, one per element, and opens only the elements owning a tagged transition in the window, so a Na D synthesis still needs no Ca file installed; `nlte_set_params` takes the whole abundance vector rather than one argument per element.  The transition table grows from 2 to 11: Na D1/D2, Mg b1/b2/b4, Ca I 4226, Ca II H and K, and the infrared triplet.  Survey behind the choice: the Amarsi et al. (2020) / Gerber et al. (2023) collection holds 17 elements (H, O, Mg, Al, Si, Ca, Ti, Cr, Mn, Fe, Co, Ni, Na, Sr, Y, Ba, Eu) and — the fact that decides everything — all sit on the same MARCS base as Na, so every Na caveat transfers element for element.  H, Fe, O, Mg and Ca are extracted locally (17.6 GB), Mg and Ca wired in.  Worth knowing: K, Li, C and N exist only through PySME/Zenodo and cover 3000–8000 K, so K I 7665/7699 — the one alkali an M-dwarf programme most wants — is precisely the one that does not reach the M-dwarf floor.  Two Ca traps recorded in the source: its model atom runs both ionization stages in one level list while `gfall` zeroes each stage separately, so E_low = 0 for both Ca I 4226 and Ca II H&K; and the weak triplet members invert easily (8498 → 4p ²P₃/₂, 8662 → 4p ²P₁/₂).  Tag counts match `gfall`'s hyperfine/isotopic splittings exactly: Ca II H&K 20, triplet 42, Mg b 3
- Two extraction traps found by doing this for elements other than Na, both now handled.  The aux index does not necessarily list every record in the file: Mg's has 56 distinct pointer gaps, all integer multiples of the record size, with 30 064 records (1.19 GB) sitting in the binary unindexed.  The original pass assumed strict contiguity and would have attached every parameter set after the first gap to the wrong record; `nlte_extract_grid.py` is now driven off the pointers themselves, which is strictly more general and costs nothing.  And Mg carries 21 records named simply `sun`, with no geometry letter and no mass — whose leading `s` reads as "spherical" if the name is parsed by position.  `nlte_build_index.py` now matches the full MARCS name pattern and excludes anything that does not fit, reporting the count.
- RESULT for Ca II and Mg I over the same 5777 / 4000 / 3000 K dwarf ladder: the cores deepen substantially while the equivalent widths barely move.  Core depths: Sun −18% (Ca II K), −10% (H), −37/−38% (Mg b1/b2), −11 to −18% (triplet); 4000 K similar; 3000 K within a few percent of LTE throughout, with the H&K cores filling IN rather than deepening.  The corresponding EW changes are +0.02 to +1.2%.  That split is the physically interesting part: these are damping-wing-dominated lines whose wings form deep where `b → 1`, so an EW-based abundance is nearly immune while anything reading the core — an S-index, a Ca II triplet gravity or velocity diagnostic, a chromospheric residual — is not.  Three distinct mechanisms.  Ca II: the ground state has `b = 1.0000` at every depth because Ca II is the dominant stage, while 4p falls to 0.82 at the top — the exact mirror image of the 3000 K Na D case, where it was the LOWER level that was pinned.  Mg I: both levels depart, `b_lo` peaking at 1.37 mid-photosphere while `b_up` falls to 0.58 at the surface.  As with Na, the MARCS atmospheres stop short of our surfaces and the cores form in exactly that region, so every core number is a lower limit
- The abundance ladder is not an axis for every element, and treating it as one would have silently broken H.  Thirteen of the seventeen grids vary A(X) at fixed atmosphere over a ±1.5 dex ladder, because a trace species barely touches the structure but strongly sets its own departure coefficients through line strength.  Two do not: `A(H) = 12.000` always — it defines the scale, and hydrogen IS the atmosphere — and `A(Fe) = [Fe/H] + 7.500` exactly, since in a scaled-solar MARCS model the iron abundance IS the metallicity.  Since the builder forms that axis as `dX = A(X) − [Fe/H]`, Fe collapses harmlessly to a single value but H would become 15 values perfectly degenerate with [Fe/H] — a 15×15 plane with only the anti-diagonal populated, so a model between two metallicity nodes would find 2 of its 4 corners missing, drop half the interpolation weight and renormalise.  It would warn, but it would stop being an interpolation in metallicity while still looking like one.  The builder now detects "A(X) never varies at fixed atmosphere" from the data itself rather than a hard-coded element list, and collapses the axis to length 1.  Verified: H and Fe collapse, O keeps its 21-value ladder, and the Mg and Ca indices are bit-identical to those built before the change
- Four out-of-bounds array accesses fixed, none of which changed a number but which together made any bounds-checked build unrunnable — so the whole class was invisible.  (1) `interp_logu_cached` wrote its hint tests as single `.AND.` chains with the range guard first, which only avoids reading past `T_GRID` if `.AND.` short-circuits, and Fortran leaves operand evaluation order to the compiler; guards are now evaluated into logicals first.  (2) `MOLEC` declared its output `NUMBER(kw,1)` while MODE 11/12 fill it to the requested ion stage; the storage was always adequate, so this was a declaration error rather than an overrun.  (3) `PFSAHA`'s generic NNN path indexed `SCALE(KSCALE)` with a scale digit that is 0 where no data is tabulated; every occurrence was verified to have a zero mantissa, so clamping the index is behaviour-preserving.  (4) `XKARZAS` took the address of `FREQN(I,N)` after a DO loop whose EXIT can fail on exact equality with the last grid point.  Spectra are bit-identical across all four on the solar and 3000 K test models, and `-fcheck=all` now runs both to completion — a debugging tool that had never been usable on this code
- Equilibrium-condensation groundwork (data layer only; the solver lands in a later change).  `data/condensates.dat` files 21 solids active above ~1000 K at photospheric pressures (corundum, perovskite, the Ti oxides, baddeleyite, the Ca–Al/Ca–Mg silicates, forsterite, enstatite, quartz, amorphous SiO, metallic Fe and Ni, VO/V₂O₃) as ln K(T) fits in one canonical form, referenced to free neutral atoms or — for the vapor-pressure-derived entries — to a gas species carried in `molecules.dat`, so the solver can evaluate supersaturation directly from its own converged densities, thermodynamically consistent with the network's own equilibrium constants.  Thermochemistry comes from the GGchem condensate compilation (Woitke et al. 2018): `tools/dustchem_loader.py` parses and evaluates every DustChem entry in GGchem's conventions, validated exact (<10⁻⁴ dex) against GGchem's own supersaturations over 1000–2600 K for all four fit forms, and `tools/fit_condensates.py` selects sources, refits over 700–2600 K (21/21 round-trip below 0.02 dex) and renders `comp_cond.pdf`.  Two deliberate source differences against GGchem are recorded in-file: anorthite (whose Sharp & Huebner entry is the known ~100 kJ/mol outlier) and ZrO₂ (0.12 dex, since the network carries no gas-phase ZrO₂).  Reference GGchem eqcond sweeps fix the appearance sequence at photospheric conditions — ZrO₂ 1590–1940 K, corundum 1530–1870 K, perovskite (the TiO sink) 1440–1810 K — i.e. at the surface temperatures of current grid-floor models
- Fe I added (11 transitions), and a tool that picks them instead of memory.  `tools/nlte_pick_transitions.py` matches both level energies of every gfall line in a window against the model atom the grid was solved with, and refuses anything ambiguous rather than taking the nearest — necessary because `atom.fe607a` carries 548 Fe I levels, many within a few cm⁻¹ of each other, where a misassignment yields a plausible-looking but wrong `b`.  The eleven rows (multiplet 4, the 5167–5173 group, and 8517/8584/8624) all match to better than 1 cm⁻¹ on both levels.  Fe II is deliberately absent: the grid's atom merges it into 58 SUPERLEVELS at term-averaged energies, so no individual Fe II line is addressable by level energy at all — every Fe II line tried fails to match, which is the correct outcome and must not be "fixed" by loosening the tolerance.  Fe II is the dominant stage here and near LTE, so little is lost.  A full scan of the Fe store also fixes the usable ceiling: levels 1–566 are finite and positive in all 852,824 cells each, while 567–607 are contaminated, so `--levels` must not reach past 566
- RESULT for Fe I: a solar effect that switches off down the ladder, and it runs the OPPOSITE way to Ca II and Mg I — the lines get WEAKER.  Solar core depths change by +17/+21/+29% (multiplet 4) and +28% (5167.7, from the ground state), with EW changes of −0.16 to −4.6% — a positive abundance correction.  At 4000 K everything is ≤ +2% and at 3000 K ≤ +1%.  The mechanism is the cleanest case yet, and it is a different one again: in the Sun `b(a⁵D)` falls to 0.188 at the surface — Fe I is a minority stage and is overionized — and for the low-excitation lines `b_l` and `b_u` fall together, giving `S_l/B_nu = 1.0001`.  So this is a pure opacity effect, not a source-function effect, unlike either Ca II or Mg I.  At 3000 K `b(a⁵D) = 1.0000` exactly, because Fe I has become the dominant stage.  That is the same argument that pinned Na I at 3000 K and pins Ca II at every temperature: three elements, one rule — the ground state of the majority ionization stage is stuck at b = 1, and every departure of consequence happens when the species you are looking at is in the minority.  Limits on the test: every model is [Fe/H] = 0 and Fe I overionization grows toward low metallicity, so these are the small end of the effect
- Validated three ways, and one of them is a genuine external test.  (i) The code: a Python re-derivation that reads the master stores rather than the runtime files, redoing cell lookup, geometry policy, corner weighting and tau remapping from scratch, reproduces every `b` SYNTHE installed to 3×10⁻⁷ relative — float32 round-off of the store.  (ii) Abundance corrections, so the results can meet a literature quoted in dex: measuring each line's curve-of-growth slope with the code itself gives solar A_NLTE − A_LTE of −0.011/−0.009/−0.012 (Mg b4/b2/b1), −0.014/−0.013/−0.007 (Ca II triplet) and +0.143/+0.070/+0.089/+0.096 (Fe I).  Every sign matches the published picture — negative for Na/Mg/Ca, positive for Fe I, whose published solar corrections reach ≈+0.12 dex for the lowest-excitation lines, which is precisely where our largest value sits.  (iii) Against the observed solar flux (IAG atlas), compared in equivalent width because EW is invariant under convolution: all four Fe I lines and both measurable Mg b lines move toward the Sun, while the three Ca II triplet lines move away by ~0.5% — expected rather than damning, since the observed IRT cores are chromospherically filled while NLTE in a radiative-equilibrium model deepens them.  The comparison also exposes two things that are not NLTE at all: Fe I 5167.7 is 74% too strong in the model (341 mÅ against 193 observed) and the NIR Fe I pair 16–24% too strong — line data, not level populations
- A trap worth knowing before any abundance experiment: an `.atm` carries its abundances TWICE, as `ABUNDANCE CHANGE` cards and again as an `ABUNDANCE TABLE` block, and `READIN` applies them in file order — so the TABLE, which comes last, silently wins.  Editing only the CHANGE cards changes nothing: a +1 dex edit produces a bit-identical spectrum, which looks exactly like a bug in the code and is not one.  `tools/perturb_abundance.py` rewrites both blocks and fails loudly if the TABLE was not touched.
- The metallicity test the solar work could not do: an A/B on a [Fe/H] = −2 dwarf (5750 K / 4.5).  NLTE is a far larger effect there, for every species.  Core depths change by −55/−53% for Ca II K/H (against −18/−10 in the Sun), −32 to −55% for Mg b, and −56 to −63% for the Ca II triplet (against −11 to −18).  The equivalent width of the Ca II triplet moves by 11–16%, against 0.7–1.2% in the Sun — large enough to matter for CaT-based metallicity and velocity-dispersion work on metal-poor systems, and systematic rather than scatter.  Abundance corrections grow by roughly an order of magnitude, to −0.07 to −0.11 dex for Mg b and −0.10 to −0.17 for the triplet, which is where the published metal-poor corrections sit.  Fe I needs a careful reading, because the naive comparison is misleading: some lines appear to SHRINK purely through saturation — at [Fe/H] = 0 they are strong and sit on the flat part of the curve of growth where a tiny EW change levers into a large dex, while at [Fe/H] = −2 they are weak and linear, where the lever is honest.  The physical quantity behaves as expected: the fractional line weakening roughly doubles.  Solar Fe I corrections from strong lines are therefore upper limits.  One number to ignore: the solar Fe I 3931.4 correction diverges because that line sits in the Ca II K wing; `tools/nlte_validate.py` now refuses any line whose measured slope falls below 5 mÅ/dex instead of printing a number that looks like a measurement
- The Cond-limit solver itself (developer flag `USE_CONDENSATION` in `mod_atlas_data`, default off — no grain opacity): condensates from `data/condensates.dat` deplete gas-phase abundances inside `NMOLEC`'s equilibrium solve, so molecular populations, opacities and n_e all respond self-consistently.  The legacy gas-phase Newton solve is untouched; condensation is an outer quasi-Newton iteration on the condensed fractions, with effective abundances feeding each gas solve and no nested chemistry evaluations.  Active-set management follows GGchem's `equil_cond` wholesale — potential-ordered activation, competitive deactivation, shared-element budget normalization, multiplicative remnant steps, progressive damping, worst-phase eviction at the cap, pure-gas fallback, per-layer warm starts.  (An earlier attempt to augment the legacy Newton directly with saturation rows failed: its tuned damping goes chaotic against log-space rows.) - The small Fe I effect is the expected one, confirmed by adding a metal-poor giant. - Made NLTE safe to run over a production grid, distinguishing installation errors (still fatal) from data gaps (never fatal).  Two things could stop or spoil a grid. - Terminal deep-CZ polish (`CZC_POLISH`, developer flag `USE_CZC_POLISH`, default on): on the final iterations the CZ-constructor block's temperatures are re-placed by a Newton solve of the node-gradient system ∇_j(T) = ∇_ad + ∇_required (tridiagonal Jacobian, banded LU; the interval-sweep construction is kept as fallback), closing the MLT flux relation to ≲0.1% where the iterative floor was 5–30%.  Two facts force it.  Deep-CZ flux balance is stiff — F_conv ∝ (∇−∇_ad)^{3/2} at ∇−∇_ad ≈ 10⁻³ demands milli-Kelvin placement, three orders below the constructor's release threshold and unreachable during iteration because each TAUSTD remap re-perturbs T at the Kelvin level (which is also why deep-CZ flux errors of tens of percent are endemic to published cool-dwarf models). - MOLEC no longer zeroes ion-stage populations in silence.  Its atomic lookup has three outcomes and the middle one was a trap: an exact code match uses the NMOLEC population, an element absent from `molecules.dat` falls through to `PFSAHA` (correct, every stage), and an element that IS in the table but lacks the requested stage got a bare `NUMBER(:, ION) = 0`.  `SELECTLINES` then discarded every line of that species on its zero-population test -- correct behaviour for a species that genuinely is not there, and therefore indistinguishable from it.  Partial coverage was worse than none: had Fe carried no row at all, the third branch would have returned all ten stages correctly; because Fe has rows for I-V, the second caught Fe VI and returned zeros.  The failure was silent at the lookup, silent at the discard, and surfaced only as `0 lines from predicted hilines.bin`, which reads as a physical statement rather than "no populations exist for these 36 species" -- which is how the entry above went unseen from Kurucz's original through the whole modernization.  `MOLZERO_RECORD` now notes each species/stage zeroed and `MOLZERO_REPORT` names them once at the end of `COMPUTE_ALL_POPS`, in one line, and only when it matters: every molecules-on run zeroes four stages per iron-group element (`NION_XNFP` asks for nine, `molecules.dat` lists five) and at photospheric temperatures zero is the right answer for the wrong reason, so the filter is a Saha estimate at the model's hottest layer against a 0.1% threshold.  The solar model prints nothing; a 10,000 K model reports 12 species, worst B IV at 223x the stage below, with `n(Fe VI)/n(Fe V) = 5.9e-2` at its 52,000 K base matching an independent estimate of 5.83e-2.  Recorded so it is not reopened: extending `molecules.dat` to stages VI-X is NOT the fix -- no regime needs molecules and stage-VI ions at once (at the hottest sub-gate layer Fe VI is 5.5% of iron but that layer is at log tau ~ 3, and the same model's tau = 1 layer has 2e-31; at 25,000 K, where those stages dominate the deep layers, switching their lines on moved the emergent flux by +0.002%), and it would widen the window in which the zeroing branch can fire rather than close it

## Data and code hygiene

- Far-infrared tails trimmed from the four ExoMol-converted molecular line files.  The Kurucz molecular ASCII wavelength field is `F10.4`, which cannot hold 100000 nm: a longer wavelength shifts every subsequent field and the reader rejects the whole record.  `tools/exomol_to_kurucz.py` had no wavelength ceiling, so `cah_owens22.dat` (615 lines), `mgh24/25/26_owens22.dat` (1003/995/1006) each ended in a block of unreadable records — reported by `read_one_diatomic_ascii` as skipped malformed lines on every ATLAS12 run since those lists became default.  They were wavelength-sorted contiguous tails of pure-rotational X-state transitions between 100 µm and 970 µm, so nothing inside the modelled flux was affected and removing them is bit-identical to the skipping the reader was already doing.  Files truncated in place (removed tails staged in `~/kurucz/superseded_linelists/gt100um_tails/`), and the converter now drops anything beyond `WL_FMT_MAX = 99999.9999` nm with a printed count, so regenerated lists cannot reintroduce it.  Kurucz's own hand-made files are unaffected: `hdxx.dat` carries its four >100 µm lines as `103330.`, dropping decimals to stay inside the field
- Hardcoded data arrays (partition functions, Feautrier matrices, Karzas–Latter tables, ionization potentials, isotope fractions) externalized to readable data files
- Dead-code audit with static call-graph analysis: ~233 lines removed from `atlas12_modules.f90`
- He I line-profile island (`HE1_GENERIC_PROFILE` and 11 helpers, ~904 lines) retained but marked `PORT INCOMPLETE` and not currently called; `stark_quasistatic_profile` handles He I until that port is completed
- All remaining Fortran 2008 `BLOCK...END BLOCK` constructs eliminated
- All routines carry descriptive header comments
